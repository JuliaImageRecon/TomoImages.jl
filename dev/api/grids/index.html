Spaces and Grids

A grid geometry places voxels in a coordinate space: voxel i has its center at origin + direction * (spacing .* (i .- 1)). The space names the coordinate system these positions are written in. Grids, Spaces and Transforms explains the conventions.

TomoImages — Module
TomoImages

Images that know where they are in space: grid geometries with an origin, a spacing, a direction and a named coordinate space; images on such grids with named dimensions; transforms between spaces; and resampling from one grid onto another, on CPUs and GPUs.

Spaces

The coordinate systems that geometries and transforms refer to.

TomoImages.AbstractSpace — Type
AbstractSpace

Supertype of coordinate spaces: the coordinate system in which the origin and direction of a grid, and the points a transform maps, are given. A space holds no numbers about other spaces; how two spaces relate is the job of transforms (AffineTransform).

A space is any value with

  • ==: whether two spaces are the same coordinate system (by default, structs compare their fields, so a parametric space such as struct Session <: AbstractSpace; id::Int; end compares by value);
  • spacename: a name for messages and displays.

Spaces should be isbits, so that geometries and transforms holding them can be passed into kernels.

Example

struct MPIScanner <: AbstractSpace end      # defined by the package that owns the space
g = GridGeometry((40, 40, 20); spacing=(1.0, 1.0, 1.0), space=MPIScanner())
source
TomoImages.DefaultSpace — Type
DefaultSpace()

The space of geometries that do not name one: for code that works in a single coordinate system, where no image ever meets an image from another scanner or session.

source
TomoImages.LPS — Type
LPS()

The patient space of DICOM: +x toward the patient's left, +y toward posterior (the back), +z toward superior (the head). See RAS for the other common convention and transform_between for the transform between both.

source
TomoImages.RAS — Type
RAS()

The patient space of NIfTI and most neuroimaging tools: +x toward the patient's right, +y toward anterior, +z toward superior. A point with coordinates (x, y, z) in LPS has the coordinates (-x, -y, z) in RAS.

source

spacename(space) -> String

The name of space in messages and displays. Defaults to the name of its type.

Grid geometries

A grid geometry, its parts, and the functions that map between voxel indices and positions. origin and direction are public but not exported, since the names are common.

TomoImages.AbstractGeometry — Type
AbstractGeometry

Supertype of geometries: maps between voxel indices and positions in a coordinate space. A geometry implements size, index_to_world, world_to_index and space. Images take any AbstractGeometry; indexing images and resample need a GridGeometry.

source
TomoImages.GridGeometry — Type
GridGeometry(size; spacing=(1, ..., 1), origin=zeros(W), direction=first N axes, space=DefaultSpace())

A regular grid of size voxels (N index dimensions) in a coordinate space with W >= N dimensions. Positions in the space are called world coordinates. Voxel i (1-based) has its center at

x = origin + direction * (spacing .* (i .- 1))
  • spacing: the distance between voxel centers along each index axis, positive (default 1).
  • origin: the center of the first voxel, in the space (default 0); its length is W.
  • direction: a W × N matrix whose columns are the unit directions of the index axes in the space (default: the first N axes of the space). The columns must be orthonormal, so a grid is rotated or reflected but never sheared; a flipped axis is a column with the opposite sign, never a negative spacing.
  • space: the coordinate space the origin and direction are given in (an AbstractSpace).

W is the length of origin, or the number of rows of direction; both must agree. The element type is the floating-point promotion of spacing, origin and direction (integers give Float64).

W > N describes a grid of lower dimension in a larger space, such as a slice of a 3D volume (see g[inds...] and TomoImages.subgrid). Lengths have no unit attached; all geometries of one application use the same (mm by convention).

Throws an ArgumentError for sizes or spacings that are not positive, a non-finite origin, or a direction whose columns are not orthonormal to within 64 * eps(Float32) (so that directions stored in Float32 pass).

Example

g = GridGeometry((64, 64, 32); spacing=(0.5, 0.5, 1.0), origin=(-15.75, -15.75, -15.5), space=LPS())
index_to_world(g, (1, 1, 1))                # the origin
fov_center(g)                               # (0, 0, 0)

TomoImages.worlddims — Function
worlddims(g)

The number of dimensions of the space of g: ndims(g) for a full grid, more for a slice.

source
TomoImages.index_to_world — Function
index_to_world(g, i)

The position of the (possibly fractional) voxel index i of g in its space, as an SVector. Integer indices give voxel centers.

source
TomoImages.world_to_index — Function
world_to_index(g, x)

The continuous voxel index of the position x in the space of g: the inverse of index_to_world. For a grid of lower dimension than its space (a slice), x is first projected onto the plane of the grid.

source
TomoImages.affine — Function
affine(g)

The (W + 1) × (N + 1) matrix of index_to_world in homogeneous coordinates: affine(g) * [i; 1] == [x; 1] for the 1-based index i and the position x.

source
TomoImages.fov — Function
fov(g)

The extent of the grid along each index axis, from the outer edge of the first voxel to the outer edge of the last: spacing .* size.

source
TomoImages.fov_center — Function
fov_center(g)

The position of the center of the grid in its space.

source
TomoImages.axiscoords — Function
axiscoords(g, d)

The coordinates of the voxel centers along index axis d, as a range, for an axis that runs along axis d of the space (column d of the direction is the unit vector e_d). Packages that take coordinate vectors per axis, such as ImagePhantoms.jl, use it for axis-aligned grids. Throws an ArgumentError for any other axis, also a flipped one (-e_d).

source
Base.isapprox — Method
isapprox(a::GridGeometry, b::GridGeometry; atol)

Whether a and b describe the same voxels: the same size and space, and voxel centers that agree to within atol (a length in the unit of the geometries; default a thousandth of the smallest voxel spacing of a); only atol is accepted. The centers are compared at the corners of the grid, which determine an affine grid completely.

source
Base.in — Method
in(x, g::GridGeometry)

Whether the position x lies inside the voxels of g: within half a voxel beyond the outermost voxel centers along every index axis. For a grid of lower dimension than its space (a slice), x is projected onto the plane of the grid; its distance from the plane is not checked.

source
TomoImages.subgrid — Function
g[inds...]
subgrid(g, inds)

The geometry of the voxels inds of g: one entry per index dimension, an integer (the dimension is dropped), a range (kept, with its step) or a colon. Every selected voxel keeps its position in the space: the origin moves to the first selected voxel, the spacing is scaled by the step, and a range with a negative step flips the direction column. Dropping a dimension keeps the space, so the result may be a slice in a space of more dimensions.
